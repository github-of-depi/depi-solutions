## Что такое LLM и как она работает на базовом уровне?

LLM (Large Language Model) — это большая языковая модель, обученная предсказывать следующий токен в последовательности на основе огромного корпуса текстов. Процесс обучения — предсказание вероятностного распределения следующего слова.

На базовом уровне принцип работы:
1. Входной текст разбивается на токены
2. Модель строит векторное представление каждого токена с учётом всего контекста (механизм внимания / attention)
3. На выходе — следующий токен с наибольшей вероятностью

Модели типа GPT-4, Claude, Llama — это transformer-based LLM, обученные на сотнях миллиардов токенов.

## Что такое токен и токенизация?

Токен — минимальная единица, с которой работает LLM. Это не обязательно слово: чаще всего токен — это ~3–4 символа для русского текста и ~4 символа для английского. Например, слово `"tokenization"` может делиться на `["token", "ization"]`.

Токенизация важна потому что:
- **Стоимость** API считается в токенах, а не в символах
- **Ограничение контекста** (context window) — тоже в токенах
- Нестандартные слова, имена или код дают больше токенов

Инструмент для проверки количества токенов: [platform.openai.com/tokenizer](https://platform.openai.com/tokenizer).

## Что такое контекстное окно (context window)?

Контекстное окно — это максимальное количество токенов (входных + выходных), которые модель может обрабатывать за один запрос. Всё, что выходит за его пределы, модель «не видит» и не может использовать.

Типичные размеры (на 2025 год):
- GPT-4o — 128 000 токенов
- Claude 3.5 Sonnet — 200 000 токенов
- Llama 3.1 — 128 000 токенов

Проблема: если документ не влезает в контекст — нужно его разбивать (chunking) или использовать RAG. Также большой контекст увеличивает стоимость и латентность запроса.

## Что такое эмбеддинг (embedding)?

Эмбеддинг — это векторное представление текста в многомерном пространстве. Тексты, похожие по смыслу, имеют близкие векторы (измеряется косинусным сходством).

Пример: фразы «купить квартиру» и «приобрести жильё» будут близко в пространстве эмбеддингов, хотя лексически они разные.

Эмбеддинги используются для:
- **Семантического поиска** — найти документ по смыслу, не по ключевому слову
- **RAG** — найти релевантные чанки документов для передачи в LLM
- **Кластеризации** и классификации текстов

Модели для эмбеддингов: `text-embedding-3-small` (OpenAI), `nomic-embed-text` (локальная).

```typescript
// Пример вызова OpenAI Embeddings API
const response = await openai.embeddings.create({
  model: 'text-embedding-3-small',
  input: 'Что такое векторная база данных?',
});
const vector = response.data[0].embedding; // массив из 1536 чисел
```

## Что такое температура (temperature) и как она влияет на ответы модели?

Temperature — параметр (0.0–2.0), который управляет «случайностью» или «творческостью» генерации токенов.

| Значение | Поведение |
|----------|-----------|
| `0.0`    | Детерминированный ответ — модель всегда выбирает наиболее вероятный токен. Хорошо для JSON, кода, фактических ответов |
| `0.7`    | Баланс между точностью и вариативностью. Хорошо для чат-ботов |
| `1.5+`   | Высокая случайность — ответы творческие, но могут быть нелогичными или бессмысленными |

Дополнительные параметры:
- **top_p** — ограничивает выбор токенов кумулятивной вероятностью (nucleus sampling)
- **top_k** — ограничивает выбор топ-k наиболее вероятными токенами

Рекомендация: для структурированных задач (JSON, SQL, код) используйте `temperature: 0`.

## Что такое галлюцинация (hallucination) и почему она возникает?

Галлюцинация — когда модель уверенно генерирует фактически неверную информацию: несуществующие источники, неправильные даты, ложные факты. Это не «ошибка» в классическом смысле — модель работает правильно, предсказывая наиболее вероятный токен, но «вероятный» ≠ «истинный».

Причины галлюцинаций:
1. Модель обучена предсказывать токены, а не верифицировать факты
2. В обучающих данных могли быть противоречия
3. Нет доступа к актуальной информации (знания ограничены датой обучения)

Способы снизить риск:
- **RAG** — давать модели контекст из реальных документов
- `temperature: 0` — снизить случайность
- Явно в промпте: «Если не знаешь — скажи "Я не знаю"»
- Проверять ответы программно (structured output + валидация)

## Чем system prompt отличается от user message?

В API LLM (OpenAI, Anthropic) переписка передаётся как массив сообщений с ролями:

- **system** — инструкции для модели: её роль, ограничения, формат ответа. Пользователь обычно не видит этот блок.
- **user** — сообщение от пользователя
- **assistant** — предыдущий ответ модели (история диалога)

```typescript
const response = await openai.chat.completions.create({
  model: 'gpt-4o',
  messages: [
    {
      role: 'system',
      content: 'Ты помощник по документации. Отвечай только на основе предоставленного контекста. Если не знаешь — скажи "Я не знаю".',
    },
    {
      role: 'user',
      content: 'Как настроить аутентификацию?',
    },
  ],
});
```

System prompt задаёт «личность» и правила поведения модели на весь диалог.
