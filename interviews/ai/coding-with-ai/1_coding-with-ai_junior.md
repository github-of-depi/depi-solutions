## Нужно ли программировать, если код пишет ИИ?

Да, это критически важно. Все абстракции «протекают»: в сложном проекте рано или поздно вылезут проблемы на уровнях, которые невозможно решить, не понимая происходящего. ИИ может предложить опасное упрощение в критичном участке — безопасности, конкурентности, работы с памятью — и без фундамента вы это не заметите.

Чтобы не растерять навыки: иногда пишите код вручную параллельно с работой ИИ, используйте LLM для понимания чужого кода, а не для полного отключения мышления.

## Какой стек технологий лучше подходит для AI-разработки?

**Статическая типизация** (TypeScript, Python с type hints) предпочтительнее — ловит многие ошибки, а ИИ не ленится писать типы. LLM лучше работают с популярными, «стандартными» языками и библиотеками, которые чаще встречались в обучающих данных.

Практические правила:
- Используйте TypeScript вместо JavaScript — ИИ генерирует более надёжный типизированный код
- Предпочитайте мейнстримные библиотеки (React, Express, Prisma) — по ним больше обучающих данных
- Новые или редкие технологии повышают вероятность ошибок и галлюцинаций
- «Оригинальничать» можно, если есть веская причина, но осознанно

```typescript
// ИИ лучше генерирует типизированный код:
interface User {
  id: string;
  email: string;
  role: 'admin' | 'user';
}

// чем:
// const user = { id: '...', email: '...', role: '...' }
```

## Зачем разработчику понимать работу LLM?

Потому что абстракции «протекают». Например, LLM видит текст токенами, а не буквами — из-за этого ошибается в подсчёте символов, делит слова неожиданно. Понимание контекстного окна помогает не забивать его мусором. Понимание механизма токенизации объясняет, почему редкие слова или код занимают больше токенов.

Конкретные примеры «утечки»:
- **Контекст заполнен** → модель «забывает» детали из начала разговора
- **Compaction** (автоматическое сжатие истории) → часть инструкций может быть потеряна
- **Температура 0** → детерминированный вывод, важно для тестов и CI
- **Токенизация кода** → длинные идентификаторы дороже коротких

## Что такое вайбкодинг и в чём его ограничения?

«Вайбкодинг» (vibe coding) — неформальный термин для подхода «пишу промпт и запускаю всё, что выдал ИИ». Работает для быстрых прототипов, но не для production: проект превращается в разрозненные куски кода, ИИ нарушает стандарты безопасности и архитектурные правила, новая фича ломает старую.

Типичные проблемы вайбкодинга:
- ИИ пишет новую функцию вместо модификации существующей
- Логику проекта приходится объяснять заново в каждом диалоге
- Нет единого источника истины — требования существуют только в голове разработчика
- Расход контекста чрезмерен, токены тратятся на повторное объяснение архитектуры

Альтернатива — **SDD (Spec-Driven Development)**: сначала спецификация, потом код.

## Какие основные AI-инструменты разработчика существуют сегодня?

Инструменты делятся на несколько категорий:

| Категория | Инструменты | Когда использовать |
|-----------|-------------|-------------------|
| **AI IDE** | Cursor, Windsurf, Kiro (Amazon) | Основная среда разработки с встроенным агентом |
| **IDE плагины** | GitHub Copilot, Codeium | Когда не хотите менять IDE |
| **CLI-агенты** | Claude Code, Aider, OpenCode | Автоматизация задач из терминала, большие рефакторинги |
| **Чат + браузер** | ChatGPT, Claude.ai | Планирование, архитектурные вопросы, анализ кода |
| **LLM API** | OpenAI, Anthropic, Ollama (локально) | Встраивание ИИ в собственные пайплайны |

Cursor и Claude Code сейчас наиболее популярны для агентной разработки — они умеют самостоятельно читать файлы, выполнять команды и делать итеративные правки.
