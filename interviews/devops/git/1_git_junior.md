## Основные команды Git?


## Что такое branch и как с ним работать?

Branch — параллельная линия разработки. Feature branches: новая фича → отдельная ветка → PR → merge в main.

```bash
git checkout -b feature/user-profile  # создать и переключиться
git push origin feature/user-profile  # отправить на remote
git checkout main                     # вернуться
git branch -d feature/user-profile   # удалить локально
```

## Что такое merge и rebase?

**merge**: объединяет две ветки, создаёт merge commit. История нелинейная, сохраняет контекст. **rebase**: переносит коммиты поверх другой ветки. История линейная, чище. Правило: не rebase публичных веток (меняет историю).

## Что такое GitHub и в чём разница с Git?

**Git** — инструмент контроля версий, работает локально на машине разработчика.

**GitHub** — онлайн-платформа, хостящая Git-репозитории и предоставляющая дополнительные инструменты для командной работы.

| | Git | GitHub |
|--|-----|--------|
| **Тип** | CLI-инструмент | Веб-сервис |
| **Где работает** | Локально | Облако | 
| **Функции** | Ветвление, коммиты, мерж | + Pull Requests, Issues, Actions, Wiki |

## Что такое git remote и как с ним работать?

`remote` — оименованная ссылка на удалённый репозиторий. По умолчанию при `git clone` создаётся remote с именем `origin`.

```bash
git remote -v                            # все подключённые remote
git remote add origin <url>             # подключить новый
git remote rename origin upstream        # переименовать
git remote remove origin                 # удалить
git remote set-url origin <new-url>     # сменить URL
```

U одного локального репо может быть несколько remote: `origin` (свой fork), `upstream` (оригинал репо).

## В чём разница между git pull и git fetch?

| | `git fetch` | `git pull` |
|--|------------|------------|
| **Что делает** | Скачивает изменения с remote | fetch + merge (или rebase) в текущую ветку |
| **Рабочее дерево** | Не изменяется | Обновляется |
| **Безопасность** | Безопасно — ничего не меняется | Может создать merge commit |

```bash
git fetch origin               # скачать, но не применять
git log HEAD..origin/main      # посмотреть, что пришло нового
git merge origin/main          # применить вручную

# Эквивалентно:
git pull                       # fetch + merge
git pull --rebase              # fetch + rebase (чище история)
```

## Что такое git stash?

`git stash` временно откладывает незакоммиченные изменения в стек и возвращает рабочее дерево в чистое состояние. Полезно, когда нужно срочно переключиться на другую ветку.

```bash
git stash                   # сохранить изменения в stash
git stash push -m "имя"    # с описанием
git stash list              # список stash-записей
git stash pop               # восстановить последний + удалить из stash
git stash apply stash@{1}   # применить без удаления
git stash drop stash@{0}    # удалить конкретный
git stash clear             # очистить весь stash
```

## Как дополнить уже сделанный коммит?

`git commit --amend` позволяет добавить изменения к последнему коммиту или отредактировать его сообщение.

```bash
# Добавить забытый файл
git add forgotten-file.ts
git commit --amend --no-edit  # добавить файл, сообщение не менять

# Исправить сообщение коммита
git commit --amend -m "Исправленное сообщение"
```

> **Важно**: `--amend` изменяет SHA коммита. Использовать **только для неопубликованных коммитов**. Если коммит уже запушен в remote, потребуется `git push --force-with-lease` (опасно для общих веток).

## Как сравнить изменения между ветками?

`git diff` — основной инструмент для сравнения изменений.

```bash
git diff main feature/auth          # все изменения между ветками
git diff main..feature/auth         # то же самое
git diff main feature/auth -- src/auth.ts  # конкретный файл
git diff --stat main feature/auth   # только статистика (сколько строк изменено)
git diff HEAD                       # текущие незакоммиченные изменения
git diff --cached                   # изменения в staging area
```
