## Что такое принцип единственной ответственности для компонентов?

Каждый компонент отвечает за одну вещь. Если компонент отображает список, загружает данные и управляет формой — надо разбить. Признаки нарушения: компонент слишком большой (>200 строк), сложно тестировать, сложно переиспользовать.

## Что такое presentational и container компоненты?

**Presentational**: только UI, получают данные через props, не знают об API. **Container**: логика, загрузка данных, управление состоянием. Современный подход: кастомные хуки заменяют container компоненты.

## Что такое Higher-Order Component (HOC)?

HOC — функция, принимающая компонент и возвращающая новый компонент с расширенной функциональностью. Например: `withAuth(Component)`, `withErrorBoundary(Component)`. Современная альтернатива: hooks + composition.

## Что такое render props паттерн?

Передача функции рендеринга через prop. Компонент вызывает её с данными. Позволяет переиспользовать логику с кастомным UI.

```typescript
<MouseTracker render={({ x, y }) => <Cursor x={x} y={y} />} />
```

## Как правильно разбивать UI на компоненты?

1. Atomic Design: atoms → molecules → organisms → templates → pages
2. По ответственности: один компонент — одна задача
3. По переиспользованию: что используется в 2+ местах → выносить
4. По изменениям: что меняется вместе → держать вместе
