## Как принимать решение о слое для нового кода?

Алгоритм:

1. Это бизнес-сущность (User, Order)? → **entities**
2. Это действие пользователя (login, checkout)? → **features**
3. Это самостоятельный UI блок (Header, Feed)? → **widgets**
4. Это страница? → **pages**
5. Используется везде, нет бизнес-логики? → **shared**

## Как мигрировать существующий проект на FSD?

Инкрементальная стратегия:
1. Создать новую FSD структуру параллельно с существующей
2. Новые фичи писать в FSD структуре
3. Постепенно переносить существующий код (начинать с shared → entities)
4. Настроить eslint для постепенного применения правил
5. Не пытаться мигрировать всё сразу — риск сломать продакшн

## Как интегрировать FSD с Next.js App Router?

App Router требует `app/` директорию. Адаптация: `app/` — Next.js роутинг (layout, page files). `src/pages/` — FSD pages слой с реальным контентом страниц. `app/page.tsx` просто рендерит FSD page компонент.

## Каковы типичные ошибки при внедрении FSD?

1. **God shared** — всё складывают в shared (разрушает изоляцию)
2. **Feature в entities** — entity содержит бизнес-действия (нарушение SRP)
3. **Перекрёстные импорты** — features импортируют из других features
4. **Слишком мелкие slices** — один компонент = один slice (избыточность)
5. **Отсутствие публичного API** — импорты вглубь slice, не через index.ts
