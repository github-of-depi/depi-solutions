## Как управлять фокусом?

При открытии модала — фокус перемещается внутрь. При закрытии — возвращается к триггеру. Focus trap — фокус не уходит из модала.

```typescript
function Modal({ isOpen, onClose, triggerRef }: Props) {
  const modalRef = useRef<HTMLDivElement>(null);
  
  useEffect(() => {
    if (isOpen) {
      modalRef.current?.focus();
      // Focus trap: prevent focus leaving modal
    } else {
      triggerRef.current?.focus(); // Вернуть фокус
    }
  }, [isOpen]);
  
  return <div ref={modalRef} tabIndex={-1} role="dialog" aria-modal="true">...</div>;
}
```

## Как тестировать a11y автоматически?

jest-axe + RTL: автоматическая проверка в unit тестах.

```typescript
import { axe, toHaveNoViolations } from "jest-axe";
expect.extend(toHaveNoViolations);

test("форма не имеет a11y нарушений", async () => {
  const { container } = render(<LoginForm />);
  const results = await axe(container);
  expect(results).toHaveNoViolations();
});
```

## Что такое aria-live regions?

`aria-live` — объявлять динамические изменения screen reader без перемещения фокуса. `polite` — объявить после текущего чтения. `assertive` — прерывает (для критичных ошибок).

```typescript
<div aria-live="polite" aria-atomic="true">
  {successMessage}
</div>
```

## Разница между role и aria-label?

`role` — определяет **тип** (семантику) элемента в accessibility tree: что это — кнопка, диалог, навигация. Скринридер объявляет роль автоматически.

`aria-label` — задаёт **имя** (доступное название) элемента, которое скринридер озвучивает вместо текстового содержимого. Используется, когда видимого текстового описания нет или оно недостаточно.

```html
<!-- role: скринридер скажет "диалог" -->
<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">
  <h2 id="dialog-title">Подтверждение удаления</h2>
</div>

<!-- aria-label: кнопка-иконка без текста -->
<button aria-label="Закрыть диалог">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Две навигации на странице — различаем по aria-label -->
<nav aria-label="Основная навигация">...</nav>
<nav aria-label="Хлебные крошки">...</nav>
```

`aria-labelledby` — ссылается на `id` уже существующего на странице текста (предпочтительнее `aria-label`, когда описание уже есть в DOM).

## Для чего используется aria-roledescription?

`aria-roledescription` позволяет переопределить озвучиваемое название роли элемента кастомной строкой. Используется, когда стандартная роль не полностью описывает компонент пользователю.

```html
<!-- Скринридер скажет "слайдер" вместо "группа" -->
<div role="group" aria-roledescription="слайдер" aria-label="Слайд 1 из 5">
  ...
</div>

<!-- Кастомный виджет "карточка продукта" вместо "статья" -->
<article aria-roledescription="карточка продукта">
  <h3>Название товара</h3>
</article>
```

> Используй осторожно: значение должно быть на языке страницы. Не злоупотребляй — стандартные роли хорошо известны пользователям скринридеров.

## Как правильно использовать заголовки H1–H6 для доступности?

Заголовки — основной способ навигации по странице для пользователей скринридеров: клавиша `H` переходит между заголовками. Нарушение иерархии ломает этот сценарий.

Правила:
- **Один `<h1>` на страницу** — главная тема документа
- **Иерархия без пропусков**: после `<h2>` идёт `<h3>`, не `<h4>`
- **Заголовки передают структуру, а не стиль** — не выбирай уровень из-за размера шрифта; кастомные размеры через CSS
- Каждый смысловой раздел страницы должен иметь свой заголовок

```html
<h1>Интернет-магазин</h1>
  <h2>Электроника</h2>
    <h3>Смартфоны</h3>
    <h3>Ноутбуки</h3>
  <h2>Одежда</h2>
```

## Правила работы с цветом для обеспечения доступности?

WCAG определяет минимальные требования к контрастности:

- **AA (обязательный)**: обычный текст — 4.5:1, крупный текст (≥18pt / ≥14pt bold) — 3:1
- **AAA (повышенный)**: обычный текст — 7:1, крупный — 4.5:1

Ключевые правила:
1. **Не передавать информацию только цветом**: ошибка формы — не только красный, но и иконка или текст
2. **Ссылки в тексте**: должны отличаться от окружающего текста нецветовым маркером (подчёркивание) или контрастностью ≥ 3:1
3. **Focus indicator**: кастомный фокус должен быть виден на любом фоне (WCAG 2.4.11)

```css
/* Хорошо: явный видимый фокус */
:focus-visible {
  outline: 2px solid #005fcc;
  outline-offset: 2px;
}

/* Плохо: убираем outline без замены */
:focus { outline: none; }
```

## Рекомендации по доступности мультимедийного контента?

**Видео:**
- **Субтитры (captions)** — синхронный текст диалогов и ключевых звуков для людей с нарушениями слуха
- **Аудиодескрипция** — голосовое описание визуального контента для незрячих
- **Транскрипт** — текстовая версия всего содержимого

**Изображения:**
- Информативные: `alt` с описанием смысла
- Декоративные: `alt=""` или `aria-hidden="true"`
- Сложные (диаграммы, графики): развёрнутое описание через `aria-describedby` или `<figcaption>`

**Анимации:**
- Автовоспроизводимый контент длиннее 5 секунд должен иметь элемент управления (пауза/стоп)
- Учитывать `prefers-reduced-motion` — отключать или упрощать анимации по запросу пользователя
