## Как масштабировать WebSocket сервер?

WebSocket — stateful (соединение привязано к инстансу). Горизонтальное масштабирование: **Redis Pub/Sub** как шина сообщений между инстансами (Socket.io Adapter), sticky sessions (клиент всегда попадает на тот же инстанс), отдельный WebSocket сервис (не с HTTP).

## Как реализовать авторизацию в WebSocket?

WS handshake — обычный HTTP запрос. Передавать токен через query parameter (не идеально — логируется) или в первом сообщении после подключения. Socket.io поддерживает `auth` option.

```typescript
// Первое сообщение после connect
ws.onopen = () => ws.send(JSON.stringify({ type: "auth", token: getToken() }));

// Сервер ожидает auth сообщение, иначе закрывает соединение
```

## Как оптимизировать трафик WebSocket?

1. **MessagePack / Protobuf** вместо JSON — бинарный формат, меньше размер
2. **Дельта-обновления** — отправлять только изменения, не весь объект
3. **Throttling** на клиенте — батчинг исходящих сообщений
4. **Compression** (`permessage-deflate`) — сжатие на уровне протокола
5. Избегать broadcast всем — отправлять только нужным

## Как обеспечить надёжную доставку сообщений?

WebSocket не гарантирует доставку при разрыве. Паттерн: sequence numbers + acknowledgement + persistent queue на сервере. При переподключении клиент сообщает последний seq, сервер досылает пропущенные.

## WebSocket vs WebTransport?

WebTransport (Chrome 97+) — новый API поверх QUIC. Поддерживает: надёжные потоки (как WebSocket), ненадёжные датаграммы (как UDP), несколько одновременных потоков без head-of-line blocking. Идеален для: игр (ненадёжные обновления позиции), стриминга медиа, real-time коллаборации.
