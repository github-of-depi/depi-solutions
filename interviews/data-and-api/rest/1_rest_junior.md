## Что такое REST?

REST (Representational State Transfer) — архитектурный стиль для API: ресурсы адресуются через URL, действия — через HTTP методы, ответы — в JSON/XML. Принципы: stateless (каждый запрос самодостаточен), uniform interface, cacheable.

## Что означают HTTP статус коды?

- **2xx** — успех: `200 OK`, `201 Created`, `204 No Content`
- **3xx** — редирект: `301 Moved Permanently`, `304 Not Modified`
- **4xx** — ошибка клиента: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `422 Unprocessable Entity`
- **5xx** — ошибка сервера: `500 Internal Server Error`, `503 Service Unavailable`

## Что такое HTTP?

**HTTP** (HyperText Transfer Protocol) — прикладной протокол передачи данных в вебе. Работает поверх TCP/IP. Клиент отправляет запрос (request), сервер возвращает ответ (response).

Версии: **HTTP/1.1** — текстовый, одно соединение на запрос; **HTTP/2** — бинарный, мультиплексирование, сжатие заголовков; **HTTP/3** — поверх QUIC/UDP.

## HTTP без сохранения состояния?

HTTP — **stateless** протокол: каждый запрос полностью независим от предыдущего. Сервер не помнит, кто делал прошлые запросы. Каждый запрос должен содержать всю необходимую информацию.

**Следствие:** сервер не знает, что запросы пришли от одного пользователя. Нужны отдельные механизмы для управления состоянием (сессии, куки, токены).

## Как решить проблему stateless HTTP?

Три подхода:

1. **Cookie** — сервер устанавливает `Set-Cookie`, браузер автоматически отправляет в каждом запросе
2. **Session** — сервер хранит состояние, клиент хранит только `session_id` в cookie
3. **Token (JWT)** — клиент хранит токен (localStorage/cookie), отправляет в заголовке `Authorization: Bearer <token>`

```http
HTTP/1.1 200 OK
Set-Cookie: session_id=abc123; HttpOnly; Secure; SameSite=Lax
```

```

Content-Type: application/json       ← Заголовки
Cache-Control: max-age=3600

[{"id": 1, "name": "Alice"}]        ← Тело ответа
```

## GET vs POST?

| | GET | POST |
|---|---|---|
| Данные | в URL (`?key=val`) | в теле запроса |
| Идемпотентный | ✓ да | ✗ нет |
| Кэшируется | ✓ да | ✗ нет |
| Безопасный | ✓ (не меняет данные) | ✗ |
| Ограничение длины | ~2000 символов URL | нет ограничений |

GET — получение данных, POST — создание или действие. GET-запросы не должны менять состояние на сервере.

## HTTP-заголовки?

Заголовки — пары ключ: значение в запросе или ответе, задают мета-информацию.

**Заголовки запроса:**
- `Authorization` — токен/credentials
- `Content-Type` — тип тела запроса (`application/json`)
- `Accept` — ожидаемый тип ответа
- `Cookie` — куки

**Заголовки ответа:**
- `Content-Type` — тип тела ответа
- `Set-Cookie` — установить куки у клиента
- `Cache-Control` — правила кэширования
- `Access-Control-Allow-Origin` — CORS политика

## HTTP vs HTTPS?

**HTTP** — открытый протокол, данные передаются в открытом виде. **HTTPS** = HTTP + TLS (Transport Layer Security). TLS обеспечивает: шифрование (данные нечитаемы третьим), аутентификацию сервера (SSL-сертификат), целостность данных.

```
HTTP:  http://  — данные читаемы при перехвате
HTTPS: https:// — данные зашифрованы, порт 443
```

Современные браузеры помечают HTTP-сайты как небезопасные. SEO: Google ранжирует HTTPS выше.

## MIME-тип?

**MIME** (Multipurpose Internet Mail Extensions) — стандарт для указания типа передаваемых данных. Формат: `тип/подтип`.

```
text/html           — HTML страница
text/css            — CSS
application/json    — JSON данные
application/javascript — JS
image/png, image/svg+xml
multipart/form-data — загрузка файлов
```

В HTTP передаётся через заголовок `Content-Type`. Браузер использует MIME-тип для выбора способа обработки ответа.

## Что такое AJAX?

**AJAX** (Asynchronous JavaScript And XML) — техника для отправки HTTP-запросов из браузера без перезагрузки страницы. Данные загружаются асинхронно, страница обновляется частично.

```javascript
// Старый способ — XMLHttpRequest
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/data');
xhr.onload = () => console.log(JSON.parse(xhr.response));
xhr.send();

// Современный способ — Fetch API
const data = await fetch('/api/data').then(r => r.json());
```

Сегодня под «AJAX» обычно подразумевают `fetch()` или axios. XML практически вытеснен JSON.

## Модель OSI?

OSI (Open Systems Interconnection) — эталонная 7-уровневая модель сетевого взаимодействия.

| # | Уровень | Протоколы |
|---|---|---|
| 7 | Прикладной | HTTP, FTP, DNS, SMTP |
| 6 | Представления | TLS/SSL, JSON/XML (условно) |
| 5 | Сеансовый | WebSocket handshake (условно) |
| 4 | Транспортный | TCP, UDP |
| 3 | Сетевой | IP, ICMP |
| 2 | Канальный | Ethernet, Wi-Fi (MAC) |
| 1 | Физический | Кабели, радиоволны |

Практическая модель TCP/IP объединяет уровни 1-2 в «Network Access» и уровни 5-7 в «Application».

## URL, URN, WWW?

**URL** (Uniform Resource Locator) — адрес ресурса в сети:
```
https://user:pass@example.com:443/path?q=1#section
  ↑       ↑          ↑       ↑   ↑     ↑   ↑
scheme  userinfo    host    port path query fragment
```

**URN** (Uniform Resource Name) — уникальное имя ресурса без указания местоположения:
```
urn:isbn:978-3-16-148410-0   — книга по ISBN
urn:uuid:6e8bc430-9c3a-...   — UUID
```

**URI** (Uniform Resource Identifier) — общее понятие, включает URL и URN.

**WWW** (World Wide Web) — система гипертекстовых документов в интернете, доступных через HTTP. Это не весь интернет, а одна из его служб (наряду с email, FTP и пр.).

## IP-адрес?

**IP** (Internet Protocol) — сетевой протокол адресации. IP-адрес — уникальный идентификатор узла в сети.

**IPv4**: `192.168.1.1` — 32 бита (~4 млрд адресов, исчерпаны).
**IPv6**: `2001:0db8::1` — 128 бит (практически бесконечно).

**Публичный IP** — уникальный в интернете. **Приватный** — локальная сеть (`192.168.x.x`, `10.x.x.x`).

## TCP, TCP/IP, UDP?

**TCP** (Transmission Control Protocol) — надёжный протокол: устанавливает соединение (3-way handshake), гарантирует доставку и порядок пакетов, контролирует перегрузку. Используется HTTP, HTTPS.

**UDP** (User Datagram Protocol) — быстрый, без гарантий доставки. Пакеты могут теряться и приходить не в порядке. Используется: видеостриминг, игры, DNS, HTTP/3 (QUIC).

**TCP/IP** — стек протоколов интернета: TCP на транспортном уровне + IP на сетевом. Фактический стандарт для передачи данных в интернете.

| | TCP | UDP |
|---|---|---|
| Соединение | ✓ | ✗ |
| Надёжность | ✓ | ✗ |
| Порядок | ✓ | ✗ |
| Скорость | медленнее | быстрее |

## DNS?

**DNS** (Domain Name System) — распределённая система для трансляции доменных имён в IP-адреса.

```
example.com → 93.184.216.34
```

**Процесс:** браузер → DNS cache → OS resolver → рекурсивный DNS (ISP) → root сервера → TLD (.com) → авторитативный DNS → IP-адрес.

**Типы DNS-записей:** `A` — домен → IPv4, `AAAA` — домен → IPv6, `CNAME` — алиас, `MX` — почтовый сервер, `TXT` — произвольный текст.

## FTP?

**FTP** (File Transfer Protocol) — протокол передачи файлов. Работает поверх TCP, использует порты 20 (данные) и 21 (управление). **SFTP** (Secure FTP) — шифрованная версия поверх SSH.

## User-Agent?

**User-Agent** — HTTP-заголовок, который браузер или клиент отправляет в каждом запросе, идентифицируя себя.

```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
            AppleWebKit/537.36 (KHTML, like Gecko)
            Chrome/124.0.0.0 Safari/537.36
```

Сервер может использовать UA для: отдачи мобильной версии, аналитики, определения возможностей браузера. Легко подделывается — нельзя доверять как средству безопасности.


## Отличие host от domain?

**Domain** — иерархическое имя в системе DNS: `example.com`, `sub.example.com`.

**Host** — сетевой узел, доступный по адресу. В контексте HTTP-заголовка `Host` — это домен + порт:

```
Host: api.example.com:8080
```

**Поддомен** — часть домена: `www.example.com` (поддомен `www`), `api.example.com` (поддомен `api`).

На одном сервере (одном IP) можно размещать разные домены — виртуальный хостинг: сервер различает их по заголовку `Host`.
