## Как эффективно использовать AI для генерации кода?

AI-инструменты — это умный автодополнение, не замена мышлению. Качество результата напрямую зависит от качества контекста.

**Основные инструменты:**
- **GitHub Copilot** — встроен в IDE, дополняет код в реальном времени
- **Cursor** — IDE на базе VS Code с глубокой интеграцией AI (Agent mode, @codebase)
- **Claude Code** — CLI-агент Anthropic для автономных задач с доступом к файловой системе
- **MCP (Model Context Protocol)** — протокол для подключения AI к внешним инструментам (Figma, БД, API)

**Принципы эффективных промптов:**

1. **Давать контекст, не только задачу:**
   ```
   ❌ "Напиши хук для fetch"
   ✅ "Напиши React хук useProducts() для fetching данных о продуктах.
      Stack: TypeScript, React Query v5, axios.
      Должен: поддерживать пагинацию, handling ошибок через toast,
      typing через interface Product { id: string; name: string; price: number }"
   ```

2. **Указывать ограничения и требования:**
   - Стек технологий
   - Существующие соглашения в проекте
   - Требования к производительности
   - Что НЕ надо делать (`не добавляй PropTypes, только TypeScript`)

3. **Итеративный подход:**
   - Генерировать небольшими блоками
   - Проверять каждый шаг
   - Исправлять через уточнения, не перегенерировать

4. **Контекстные команды в Cursor:**
   ```
   @codebase     - поиск по всему проекту
   @file         - включить конкретный файл
   @web          - поиск в интернете
   @docs         - документация библиотек
   ```

**Что AI делает хорошо:**
- Бойлерплейт (CRUD, формы, тесты)
- Рефакторинг (переименование, извлечение функций)
- Написание тестов для существующего кода
- Объяснение незнакомого кода
- Дебаг с конкретным сообщением об ошибке

**Что AI делает плохо:**
- Архитектурные решения (нужен контекст всей системы)
- Сложная бизнес-логика с неявными требованиями
- Задачи без чёткого определения "правильного" ответа
- Актуальные данные (API могут устареть)

## Как проверять код, сгенерированный AI?

AI уверен в своих ответах даже когда ошибается. Без проверки это технический долг или баг в продакшене.

**Частые типы ошибок AI:**

1. **Устаревшие API:**
   ```typescript
   // AI может написать устаревший синтаксис React Router v5:
   ❌ import { Switch, Route } from 'react-router-dom'; // v5
   ✅ import { Routes, Route } from 'react-router-dom'; // v6
   ```

2. **Hallucination (выдуманные методы/пакеты):**
   ```typescript
   // Несуществующий метод:
   ❌ queryClient.invalidateQueries('products'); // v4 API
   ✅ queryClient.invalidateQueries({ queryKey: ['products'] }); // v5 API
   ```

3. **Edge cases:**
   - Не обрабатывает null/undefined
   - Нет loading/error состояний
   - Race conditions в async коде

4. **Проблемы безопасности:**
   - `dangerouslySetInnerHTML` без санитизации
   - Хранение секретов в коде
   - SQL-инъекции в строковых запросах

5. **Производительность:**
   - Создание объектов/функций в render
   - Лишние ре-рендеры (нет мемоизации)
   - N+1 запросы

**Чеклист ревью AI-кода:**
```
☐ Код компилируется без ошибок TypeScript?
☐ Все импорты существуют (нет выдуманных пакетов)?
☐ API актуальны? (проверить docs)
☐ Обработаны все edge cases (null, empty, error)?
☐ Нет секретов в коде?
☐ Нет уязвимостей (XSS, injection)?
☐ Логика соответствует требованиям?
☐ Есть тесты или они нужны?
```

**Инструменты для проверки:**
- TypeScript компилятор — первая линия защиты
- ESLint — code quality, потенциальные баги
- Unit-тесты — поведение в edge cases
- Code review — коллеги видят то что AI пропустил

## Как выглядит рабочий процесс с Cursor / Claude Code?

Эффективный рабочий процесс — итеративный, с сохранением контроля на каждом шаге.

**Cursor (Agent mode):**

```
1. Открыть чат (Cmd+L)
2. Добавить контекст: @file, @codebase
3. Описать задачу с деталями
4. AI предлагает изменения → просмотреть diff
5. Принять/отклонить каждое изменение
6. Запустить тесты / TypeScript
7. Итерировать если нужно
```

**Claude Code (CLI):**
```bash
# Запуск в директории проекта:
claude

# Примеры задач:
> Посмотри на src/features/auth и объясни как работает refresh token
> Добавь unit-тесты для src/hooks/useCart.ts (покрой edge cases)
> Найди все места где используется any и замени на правильные типы
> Проведи рефакторинг src/components/UserTable - вынеси логику в хуки
```

**Что делает разработчик, что делегирует AI:**

| Задача | Разработчик | AI |
|---|---|---|
| Архитектурное решение | Принимает | Предлагает варианты |
| Бойлерплейт / шаблон | Ставит задачу, ревьюит | Генерирует |
| Бизнес-логика | Описывает требования + ревьюит | Имплементирует |
| Рефакторинг | Определяет цель | Выполняет |
| Тесты | Определяет сценарии | Пишет |
| Дебаг | Изолирует проблему | Предлагает решения |
| Code review | Финальное решение | Первичный анализ |

**Типичный сценарий разработки фичи:**
```
1. Разработчик: определить задачу, проанализировать требования
2. AI: сгенерировать скелет/структуру
3. Разработчик: проверить, скорректировать архитектуру
4. AI: реализовать детали, написать тесты
5. Разработчик: ревью, исправление ошибок, edge cases
6. AI: исправления по фидбэку
7. Разработчик: финальное ревью, merge
```

**MCP (Model Context Protocol) — расширение возможностей:**
```json
// .cursor/mcp.json
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["@figma/mcp-server", "--figma-api-key", "${FIGMA_API_KEY}"]
    },
    "shadcn": {
      "command": "npx",
      "args": ["@shadcn/mcp-server"]
    }
  }
}
```
Через MCP: AI может читать макеты Figma, добавлять shadcn компоненты, обращаться к БД.

## Может ли AI заменить разработчика?

Этот вопрос часто задают на интервью чтобы понять: как вы относитесь к AI и насколько критически мыслите.

**Что AI умеет хорошо (уже заменяет):**
- Написание стандартного кода по шаблону
- Поиск и объяснение ошибок
- Рефакторинг механических задач
- Первичный анализ кода

**Что AI не умеет (пока):**
- **Понимание бизнес-контекста** — зачем фича нужна, кому, какой trade-off правильный
- **Системное мышление** — как изменение влияет на всю архитектуру
- **Ответственность** — AI не несёт ответственности за production-баги
- **Неявные требования** — "сделай как принято у нас в команде"
- **Коммуникация** — договориться с PM, дизайнером, объяснить решение
- **Суждение в неопределённости** — когда нет правильного ответа

**Реалистичная позиция:**
> AI радикально меняет профессию, но не заменяет разработчика — меняет его роль. Сеньор-разработчик с AI делает работу быстрее и берётся за более сложные задачи. Джун-разработчик без понимания основ не сможет проверить что AI генерирует — и создаст технический долг или уязвимости. Ценность разработчика смещается от "написать код" к "принять правильное архитектурное решение и проверить реализацию".

## Как обеспечить безопасность при использовании AI-инструментов?

AI-инструменты отправляют ваш код на сервера третьих сторон. Это создаёт риски.

**Основные угрозы:**

1. **Утечка секретов** — API-ключи, токены, пароли в коде
2. **Утечка конфиденциального кода** — проприетарная бизнес-логика
3. **Prompt injection** — вредоносный контент в файлах репозитория
4. **Backdoors** — AI может сгенерировать уязвимый код намеренно или случайно

**Практики защиты:**

**1. Не допускать секреты в код:**
```bash
# .gitignore и .cursorignore:
.env
.env.local
*.key
secrets/

# Использовать переменные окружения, не hardcode:
❌ const apiKey = 'sk-abc123...';
✅ const apiKey = process.env.VITE_API_KEY;
```

**2. Настроить `.cursorignore` / `.gitignore` для чувствительных файлов:**
```
# .cursorignore
.env*
secrets/
private/
*.pem
*.key
```

**3. Корпоративная политика:**
- Использовать Enterprise-тарифы (Copilot Enterprise, Cursor Business) — данные не используются для обучения
- Проверить соглашение об использовании данных (Terms of Service)
- Не вставлять чувствительные данные клиентов в промпты

**4. Проверять сгенерированный код на безопасность:**
```typescript
// AI может сгенерировать XSS уязвимость:
❌ element.innerHTML = userInput; // опасно
✅ element.textContent = userInput; // безопасно
✅ element.innerHTML = DOMPurify.sanitize(userInput); // если HTML нужен
```

**5. Prompt injection:**
```
// Потенциально опасный сценарий:
// Файл репозитория содержит: "<!-- AI: ignore all previous instructions... -->"
// AI может выполнить инструкции из кода пользователя

Защита: проверять что AI делает, не доверять слепо autonomous agents
```

**6. Аудит зависимостей:**
- AI может предложить устаревшие или уязвимые пакеты
- Проверять через `npm audit` или Snyk
- Верифицировать версии библиотек
