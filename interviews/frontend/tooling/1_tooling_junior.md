## Зачем нужен bundler?

Bundler (Vite, Webpack) объединяет множество JS/CSS/image файлов в оптимизированные бандлы для браузера: разрешает импорты, минифицирует, разделяет на chunks, оптимизирует загрузку. Без него браузер делал бы тысячи HTTP запросов за каждым файлом.

## В чём разница между npm, yarn и pnpm?

**npm** — стандартный менеджер Node.js. **yarn** — появился как альтернатива с lockfile и рабочими пространствами. **pnpm** — современный, экономит дисковое пространство через hard links, строгий (нет доступа к пакетам не из dependencies), быстрее установка. pnpm — тренд для monorepos.

## Зачем нужен TypeScript/Babel?

**TypeScript** — типизация + современный JS → компиляция в совместимый JS. **Babel** — трансфоримирует современный JS/JSX в совместимый с целевыми браузерами. SWC — быстрая Rust-based альтернатива Babel. Vite использует esbuild/SWC для dev, Rollup для production.

## Что такое .env файлы?

`.env` файлы хранят переменные окружения: API ключи, URLs, feature flags. Не должны попадать в git (`.gitignore`). `.env.local` — локальные переопределения. Vite: переменные с `VITE_` префиксом доступны в браузере через `import.meta.env`.

## Что такое package.json scripts?

`scripts` — объект с именованными командами, выполняемыми через `npm run`. Можно использовать локально установленные пакеты без глобальной установки. `pre`/`post` hooks — автоматически выполняются до/после скрипта.

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview",
    "test": "vitest",
    "lint": "eslint src"
  }
}
```

## Для чего нужен package-lock.json?

`package-lock.json` — лок-файл, который фиксирует **точные версии** всех зависимостей (включая транзитивные). Гарантирует воспроизводимость борда: у всех разработчиков и CI/CD одинаковый набор пакетов.

```json
// package.json — диапазон версий (неточно)
{ "react": "^18.0.0" }

// package-lock.json — зафиксированная версия (точно)
{ "react": { "version": "18.3.1", "resolved": "...", "integrity": "..." } }
```

**Правила:**
- Всегда коммитить `package-lock.json` в git
- Никогда не редактировать вручную
- Yarn использует `yarn.lock`, pnpm — `pnpm-lock.yaml`

## npm install vs npm ci — в чём разница?

| | `npm install` | `npm ci` |
|---|---|---|
| Обновляет lock | да | нет |
| Удаляет node_modules | нет | да, всегда |
| Зависит от lock-файла | не строго | строго (ошибка если lock/json расходятся) |
| Использование | локальная разработка | CI/CD пайплайны |
| Скорость | медленнее | быстрее |

```bash
# Локально — когда добавляешь/обновляешь зависимости
npm install react@19

# CI/CD — повторяемая чистая установка по lock-файлу
npm ci
```

**Правило:** в CI всегда использовать `npm ci` — быстрее и детерминировано.
