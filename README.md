### Обзор проекта `depi-solutions`

Этот репозиторий предназначен для накопления и переиспользования инженерных знаний.  
Каталог `ai/` содержит накопления знаний в ИИ направлении: инструкции, шаблоны и заготовки, которые можно быстро подключать к любым вашим проектам.

### Структура каталога `ai/`

```text
depi-solutions/
└── ai/
    ├── .shared/
    │   ├── common/                           # Общие для всех проектов инструкции
    │   │   ├── security.md                   # Принципы безопасности
    │   │   ├── documentation.md              # Как писать комментарии и доки
    │   │   ├── code-review.md                # Чеклист для ревью
    │   │   └── git-commit.md                 # Правила коммитов
    │   │
    │   └── stacks/                           # Инструкции по конкретным стекам
    │       ├── react-only/                   # Чистый React (без Next.js)
    │       │   ├── react-best-practices.md
    │       │   ├── hooks-rules.md
    │       │   ├── styling.md                # CSS-in-JS, CSS Modules и т.д.
    │       │   └── testing.md                # Тестирование React-компонентов
    │       │
    │       ├── react-next/                   # React + Next.js
    │       │   ├── react-best-practices.md   # Может отличаться от react-only
    │       │   ├── next-specific.md          # App Router, SSR, middleware
    │       │   ├── styling.md                # Подходы к стилям (CSS Modules, Tailwind и др.)
    │       │   └── testing.md                # Тестирование Next.js-приложений
    │       │
    │       ├── fastapi-sqlalchemy/           # Бэкенд: FastAPI + SQLAlchemy
    │       │   ├── project-structure.md
    │       │   ├── api-design.md
    │       │   ├── db-models.md
    │       │   └── testing.md
    │       │
    │       └── ...                           # Другие стеки, которые вы используете
    │
    ├── copilot/
    │   └── templates/                        # Шаблоны для GitHub Copilot
    │       ├── single-prompt.md.j2           # Одноразовый промпт
    │       └── instructions-file.md.j2       # Файл с постоянными инструкциями
    │
    └── cursor/
        └── templates/                        # Шаблоны для Cursor
            ├── rule.mdc.j2                   # Шаблон для одного RULE.md
            └── multiple-rules.mdc.j2         # Шаблон для нескольких RULE-файлов
```

> Структура может немного отличаться от текущего состояния репозитория — treat её как целевой ориентир. При добавлении новых файлов поддерживайте эту идею организации.

### Концепция `.shared/`

- **`common/`**: инструкции, которые применимы к любым проектам.
  - Безопасность (`security.md`).
  - Документация и комментарии (`documentation.md`).
  - Правила код-ревью (`code-review.md`).
  - Стиль и правила коммитов (`git-commit.md`).
- **`stacks/`**: инструкции под конкретные технологические стеки.
  - Внутри каждой папки стека лежат **только специфичные** для этого стека инструкции.
  - Общие вещи не дублируются, а подключаются из `common/`.

Идея: при генерации настроек/правил для проекта вы всегда берёте:

1. **Общие инструкции** из `ai/.shared/common/`.
2. **Стек-специфичные инструкции** из нужной папки в `ai/.shared/stacks/` (например, `react-next/`).

### Как использовать это с ИИ (Cursor, Copilot)

- **Для Cursor**:
  - Берёте нужный стек (например, `ai/.shared/stacks/react-next/`).
  - Добавляете к нему общие инструкции из `ai/.shared/common/`.
  - На основе этого генерируете `RULE.md` или несколько правил через шаблоны в `ai/cursor/templates/`.

- **Для GitHub Copilot**:
  - Берёте те же инструкции (`common/` + выбранный стек).
  - Используете шаблоны в `ai/copilot/templates/`:
    - `single-prompt.md.j2` — для разового промпта.
    - `instructions-file.md.j2` — для постоянного файла с инструкциями.

### Идея манифестов стеков (опционально)

В будущем вы можете добавить в каждую папку стека файл-манифест (например, `manifest.json` или `index.md`), где будет:

- Список файлов из `common/`, которые нужно подключать.
- Список локальных файлов стека (React, Next, БД и т.п.).

Тогда достаточно будет передавать ИИ содержимое папки стека и манифест — без ручного перечисления нужных общих файлов.

### Как расширять репозиторий

- **Добавить новый стек**:
  - Создайте папку в `ai/.shared/stacks/` (например, `nestjs-prisma/`).
  - Опишите в ней:
    - Общую структуру проекта.
    - Специфику фреймворка/БД.
    - Правила тестирования.
    - Особенности архитектуры и стиля кода.
- **Добавить общую инструкцию**:
  - Положите новый файл в `ai/.shared/common/`.
  - Название должно ясно описывать область (например, `logging.md`, `error-handling.md`).

Так вы превращаете `depi-solutions/ai/` в вашу личную «базу знаний», которую ИИ может использовать для настройки любых будущих проектов.
