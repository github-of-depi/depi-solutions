# depi-solutions

Репозиторий для подготовки к техническим собеседованиям и накопления инженерных знаний. Материалы написаны на **русском языке**.

---

## Что здесь есть

### `interviews/` — вопросы и ответы

Теоретические вопросы, разбитые по темам и уровням сложности. Каждый файл — это отдельный уровень одной темы: Junior, Middle, Senior, Expert.

### `tasks/` — практические задачи

Задачи на написание кода: алгоритмы, функции, реальные сценарии. Организованы так же, как `interviews/` — по темам и уровням. Каждая задача содержит описание, пример, скрытое решение.

### `ai/` — AI-инструменты

Промпты, инструкции и шаблоны для GitHub Copilot и Cursor — подключай к своим проектам.

## Уровни сложности

| Префикс | Уровень | Описание |
|---------|---------|----------|
| `1_`    | Junior  | Основы, определения, базовое использование |
| `2_`    | Middle  | Паттерны, trade-offs, реальные сценарии |
| `3_`    | Senior  | Архитектура, edge cases, производительность, внутренняя работа |
| `4_`    | Expert  | Глубокие внутренности, системный дизайн, собственные реализации |

## Связи между вопросами и задачами

Каждый вопрос в `interviews/` может ссылаться на связанные практические задачи в `tasks/`, и наоборот. Это позволяет не просто выучить теорию, но и закрепить её практикой.

```
interviews/frontend/javascript/2_javascript_middle.md
  └── ## Что такое замыкание?
        └── Связанные задачи → tasks/frontend/javascript/2_javascript_middle.md#задача-с-замыканием

tasks/frontend/javascript/2_javascript_middle.md
  └── ## Задача с замыканием
        └── Связанные вопросы → interviews/frontend/javascript/2_javascript_middle.md#что-такое-замыкание
```

## Как использовать

1. Выбери тему и уровень: например, `interviews/frontend/react/2_react_middle.md`
2. Прочитай вопросы и попробуй ответить самостоятельно
3. Открой ответ, сравни с тем, что сказал бы на интервью
4. Перейди по ссылке «Связанные задачи» и реши задачу
5. Используй «Материалы для изучения» для углублённого изучения темы

## Как внести вклад

Мы приветствуем любые улучшения! Вот как можно помочь:

- **Добавить вопрос** — найди нужный файл в `interviews/`, добавь Q&A по шаблону из [промпта](ai/prompts/create-interview-file.prompt.md)
- **Добавить задачу** — создай или дополни файл в `tasks/` по тому же шаблону
- **Исправить ошибку** — опечатка, устаревший ответ, неработающая ссылка
- **Добавить материалы** — ссылки на статьи, видео, документацию к существующим вопросам
- **Предложить новую тему** — создай issue с описанием темы и почему она важна

### Правила контрибуции

1. Все вопросы и ответы — **на русском языке**
2. Следуй структуре файлов из [промпта](ai/prompts/create-interview-file.prompt.md)
3. Не дублируй вопросы, которые уже есть в других файлах той же темы
4. Код — в блоках с полным названием языка: ` ```typescript `, ` ```javascript `
5. Создавай отдельную ветку и открывай Pull Request

### Концепция `.shared/`

- **`common/`**: инструкции, которые применимы к любым проектам.
  - Безопасность (`security.md`).
  - Документация и комментарии (`documentation.md`).
  - Правила код-ревью (`code-review.md`).
  - Стиль и правила коммитов (`git-commit.md`).
- **`stacks/`**: инструкции под конкретные технологические стеки.
  - Внутри каждой папки стека лежат **только специфичные** для этого стека инструкции.
  - Общие вещи не дублируются, а подключаются из `common/`.

Идея: при генерации настроек/правил для проекта вы всегда берёте:

1. **Общие инструкции** из `ai/.shared/common/`.
2. **Стек-специфичные инструкции** из нужной папки в `ai/.shared/stacks/` (например, `react-next/`).

### Как использовать это с ИИ (Cursor, Copilot)

- **Для Cursor**:
  - Берёте нужный стек (например, `ai/.shared/stacks/react-next/`).
  - Добавляете к нему общие инструкции из `ai/.shared/common/`.
  - На основе этого генерируете `RULE.md` или несколько правил через шаблоны в `ai/cursor/templates/`.

- **Для GitHub Copilot**:
  - Берёте те же инструкции (`common/` + выбранный стек).
  - Используете шаблоны в `ai/copilot/templates/`:
    - `single-prompt.md.j2` — для разового промпта.
    - `instructions-file.md.j2` — для постоянного файла с инструкциями.

### Идея манифестов стеков (опционально)

В будущем вы можете добавить в каждую папку стека файл-манифест (например, `manifest.json` или `index.md`), где будет:

- Список файлов из `common/`, которые нужно подключать.
- Список локальных файлов стека (React, Next, БД и т.п.).

Тогда достаточно будет передавать ИИ содержимое папки стека и манифест — без ручного перечисления нужных общих файлов.

### Как расширять репозиторий

- **Добавить новый стек**:
  - Создайте папку в `ai/.shared/stacks/` (например, `nestjs-prisma/`).
  - Опишите в ней:
    - Общую структуру проекта.
    - Специфику фреймворка/БД.
    - Правила тестирования.
    - Особенности архитектуры и стиля кода.
- **Добавить общую инструкцию**:
  - Положите новый файл в `ai/.shared/common/`.
  - Название должно ясно описывать область (например, `logging.md`, `error-handling.md`).

Так вы превращаете `depi-solutions/ai/` в вашу личную «базу знаний», которую ИИ может использовать для настройки любых будущих проектов.
